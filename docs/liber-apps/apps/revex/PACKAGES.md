# Project procurement packages

The Packages workspace reproduces the 47 contractor folders in the supplied Winthrop template. `packages-core.js` owns a deterministic metadata classifier shared by the UI and Drive export. Source names, categories and folders establish trade membership; file extensions and MIME types select source applications. Common architectural, structural, energy and ceiling references can serve multiple trades. Unknown formats, ambiguous names and conflicting project addresses remain visible for review. Manual assignments are persistent and survive rebuilding.

The app reads the existing REVEX Store, canonical Design Book positions and the linked Spec Book. Quantities come from source fields; assigning a package never approves a selection or authorizes procurement. Source links, descriptions, quantities, units, statuses and application routes remain available together. No BIM or source document is rewritten.

`packages-store.js` extends the existing Store with hidden project-library records: configuration, hashed assignment IDs, source pages and one expiring transaction lock. New source generations commit their pointer last; the preceding pages are removed only after success. All writes retain existing project membership rules. Project/account changes cancel pending results and clear the UI.

`packages-drive.js` uses the existing Google browser OAuth client with Drive scope, held only in memory. Connect Drive is separate from REVEX sign-in and must be renewed when Google consent expires (normally about an hour). The selected project folder must have the same normalized name as the active project and be a writable descendant of the configured LIBER-PROJECTS root.

Sync creates `012_PACKAGES`, the 47 trade folders, and `00_PROJECT_REFERENCES`. It produces linked HTML indexes and native Drive shortcuts. Sources retain their original locations and permissions. Repeated syncs reconcile shortcuts by stable Drive file ID; only obsolete shortcuts marked as this feature's output may be trashed. Manually added files are preserved. Initial desktop-provisioned HTML indexes can be adopted only when their exact schema marker is present.

REVEX sources update through existing live subscriptions. Opted-in Drive projection runs after debounced source changes and checks external files every 15 minutes while the browser session is visible and consent is valid. It also refreshes when returning to the tab. There is no unattended server-side Drive credential, webhook or background sync after the browser closes. HTML indexes are snapshots; live package links open the current authorized project. Initial folders include linked indexes; native shortcuts are reconciled by the first consented Drive sync.

The initial rollout provisioned 22 building-project roots and bound the four matching REVEX projects. The distinct 89 Winthrop project was not mapped to 87 Winthrop. Software projects, shared libraries and external-share mirrors were excluded from construction-package provisioning.

Run `node --test tests/revex-packages*.test.cjs`. Tests cover trade mappings, source quantities, ambiguous sources, project conflicts, escaping, archive handling, Drive idempotency, source preservation, project cancellation and interrupted source generations. Browser verification includes real Firebase project rules and transactions, assignment persistence, WALLT navigation, desktop/mobile layouts and logout isolation. Preview sign-in uses a candidate asset overlay at the authorized production origin because the API key intentionally rejects temporary Hosting preview origins.
